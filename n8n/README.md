# FlowPilot n8n workflow

`lead-pipeline.json` is an importable n8n definition, generated by `scripts/generate-workflow.py`. The version baseline is n8n **2.46.6**, verified against the official stable documentation and npm registry on 2026-11-05. Import/execution evidence is recorded separately in `docs/VERIFICATION.md`.

**The JSON requires the bundled `CUSTOM.flowPilotWebhook` trigger.** Docker Compose installs it through the supported `N8N_CUSTOM_EXTENSIONS` mount. For a native n8n process, set `N8N_CUSTOM_EXTENSIONS` to this project’s absolute `n8n/custom-nodes` directory and restart n8n before importing. The TypeScript source and ready-to-load CommonJS `.node.js` are both included; no n8n engine file is patched.

## What it executes

| Path | Nodes |
| --- | --- |
| Normal intake | Authenticated Webhook → claim → extraction LLM service → rules → CRM → draft LLM service → approval checkpoint |
| Missing/ambiguous information | Rules → review checkpoint, with `needs_review` preserved |
| Unrelated enquiry | Rules → CRM archive → finish; no draft |
| Approved action | Authenticated Webhook with delivery phase → claim → delivery service → finish |
| Exhausted service-call failure | Limited HTTP retries → failure recording → native Stop And Error |
| Duplicate/stale dispatch | Claim denies progression → no-op |

The model requests live in the FastAPI `extract` and `draft` steps, so the JSON export contains no model key or customer text. Every call uses an internal credential plus the dispatch fence and `$execution.id`. The backend validates execution ownership, phase, order, persisted approval and idempotency; calling the delivery webhook does not authorize email.

## Why approval does not use a long n8n Wait URL

The pending draft and versioned human decision are durable business data. The pipeline ends when that checkpoint commits. A later approval queues a separate delivery dispatch. This avoids treating a resumable n8n URL as human authorization and survives worker restarts. The UI exposes business `waiting_approval` independently from native n8n execution status.

## Credentials

- Type: `httpHeaderAuth`.
- ID: `flowpilotInternalHeader1`.
- Display name: `FlowPilot internal API`.
- Header name: `x-flowpilot-internal`.
- Value: the private deployment's `FLOWPILOT_INTERNAL_KEY`.

The same credential authenticates the custom Webhook and all internal HTTP requests. The custom trigger performs a length-checked constant-time comparison, rejects unexpected payload fields and emits only the three dispatch fields. Its purpose is to prevent the built-in Webhook’s request-header output from persisting the internal authentication key in native execution history. Keeping full native history is safe only when using the supplied sanitized trigger; do not replace it with a generic header-emitting trigger. `scripts/import-n8n.py` imports the private temporary credential file and workflow, publishes the workflow, removes the temporary files, then restarts and checks the dedicated n8n service. No secret belongs in `lead-pipeline.json`.

## Installation

Finish n8n owner setup, then run in a maintenance window. This deployment operation restarts the dedicated Compose n8n service; active executions may be interrupted:

```bash
python3 scripts/import-n8n.py
```

For a separate test deployment:

```bash
python3 scripts/import-n8n.py --env-file .env.test
```

If the first-run owner or project is missing, the import helper fails with a setup instruction. It never disables n8n user management. The installed **2.46.6** CLI's `publish:workflow` implementation updates the database and explicitly instructs a running instance to restart. The helper therefore runs `docker compose restart --no-deps --timeout 30 n8n` after confirming temporary-file removal; it does not rely on a publication polling service or a 15-second delay.

After restart, a bounded check posts `{}` to `http://127.0.0.1:5678/webhook/flowpilot` from inside the n8n container, without an authentication header. Only HTTP **401** with the bundled trigger's `error=UNAUTHORIZED` response confirms readiness; another login wall or 404 does not count. Authentication rejects this request before workflow data is emitted, so no valid business dispatch or secret is sent. The default readiness deadline is 120 seconds, configurable with `--ready-timeout` from 1 to 600 seconds. Individual Docker commands and probe requests also have time limits.

Cleanup, restart or readiness failure produces a nonzero exit code and recovery commands. If cleanup cannot be confirmed, the helper does not restart. It never reports overall deployment success merely because import/publish commands exited successfully. Repair the cause and rerun the helper in a maintenance window.

Create a Public API key in n8n settings and use `scripts/configure-n8n-status.py` to enable native status reconciliation. Recreate API/worker afterward. Do not infer native success from the business checkpoint alone.

## Local process testing

For n8n and FastAPI running as local processes rather than Compose:

```bash
python3 scripts/generate-workflow.py --api-base http://127.0.0.1:8000 --output /tmp/flowpilot-local-workflow.json
```

Import that file into your local n8n instance and create/bind the credential with the same internal key as the backend. Configure `N8N_WEBHOOK_URL` and `N8N_BASE_URL` to its actual local address. Also set `N8N_CUSTOM_EXTENSIONS` as described above. If publishing with the pinned CLI, restart the native process afterward and verify webhook registration. Do not rewrite the production JSON with a host-specific URL just to run one test.

## Recovery

Use FlowPilot's execution recovery action after fixing the cause. It rotates the dispatch fence and reuses already committed effects. A native n8n replay using obsolete input can be rejected as stale; that is deliberate. Repeated approvals and delivery callbacks must never create a second outbox row. For ambiguous SMTP outcomes, reconcile before any new authorized action.

## Trigger security regression

```bash
node --test n8n/custom-nodes/FlowPilotWebhook.test.cjs
```

To rebuild the included JavaScript after editing its TypeScript source, install frontend dependencies and run `node scripts/build-n8n-node.cjs` from the project root. Native acceptance should also scan the saved execution data for credential retention without printing the credential.

## Import-helper regression

```bash
python3 -m unittest discover -s scripts/tests -p test_import_n8n.py -v
```

These six checks use a controlled Docker CLI and JavaScript fetch responses. They verify cleanup/restart ordering, bounded failure, credential redaction and the exact unauthenticated readiness response. They do not start Docker containers; see `artifacts/n8n-import-verification.json` for the recorded scope.
